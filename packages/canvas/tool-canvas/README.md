# @deepseek-ai/dsh-tool-canvas

English | [中文](README.zh.md)

`dsh-tool-canvas` gives an Agent one high-level `canvas` tool for user-visible Infinite Canvas work. The tool owns model input validation and the durable command record; the Web client and Infinite Canvas own delivery and execution.

The shipped Web `standard` and `code` Agent presets mount this package. Headless composition continues to use the base tool tree and does not expose `canvas`.

## Tool

`canvas(action: "generate", prompt, nodeId?, model?)` appends one `canvas/command` event to the calling Agent's Session. The returned `{ accepted, commandId, action }` confirms that the command was committed to the Session log; it does not claim that the browser received it or that image generation succeeded.

`prompt` is trimmed and must remain non-empty. Blank optional `nodeId` and `model` values are treated as omitted. `commandId` is generated by the Host and remains stable through Web delivery so the Canvas side can deduplicate the command.

With no `nodeId`, the classic Canvas uses a selected image-generator node when one is active; otherwise it creates a prompt node and image-generator node, connects them, and starts that generator. With `nodeId`, the Canvas requires that exact existing node to be an image generator. When `model` is present, the Canvas applies it to the target generator and remains authoritative for provider/model compatibility.

## Delivery semantics

`canvas/command` is durable for audit and session persistence, but browser execution is intentionally live-only. The Web runtime emits each newly arriving `session/event` through `session/live-event`; `ui-layout` projects the latest Canvas command per Session and sends only the current Session's unseen sequence to the versioned Infinite Canvas bridge. Opening stored history does not replay commands, so reload and resume cannot repeat old side effects.

The top-level Infinite Canvas frame routes `host:command` only to an open classic Canvas. Canvas list and unsupported editors return an explicit command failure. The classic Canvas validates the command again, deduplicates by `commandId`, mutates its existing graph model, and returns `canvas:command-result` to Harness. Phase 1 keeps this acknowledgement transient rather than adding another durable Session event.

## Config

There is no package configuration in Phase 1. Canvas provider/model settings remain owned by Infinite Canvas.

## Model Experience

### System prompt

#### What the model sees

This package adds no system-prompt section. Availability is communicated by the `canvas` tool schema.

#### Token effect

No prompt-token cost beyond the tool schema. A successful call contributes the compact rendered result `Canvas queued generate command <commandId>.` to normal tool-result context.

#### KV Cache effect

The schema is prefix-stable while the package version and mounted preset remain unchanged. Calls and results append after the reusable request prefix.

### Tool schema and result

#### What the model sees

The schema exposes one `generate` action with required `prompt` and optional `nodeId`/`model`. Success returns `{ accepted: true, commandId, action: "generate" }`; Canvas execution failures are not reflected into that already-completed tool call.

#### Token effect

Fixed schema cost plus one short result per call. The durable `canvas/command` event itself is log-only and does not enter model history.

#### KV Cache effect

The schema remains cacheable across turns; generated `commandId` values occur only in post-prefix tool results.

## Known Limitations and Deferred Work

- Phase 1 supports classic-Canvas image generation only. Video, editing, multi-step workflow construction, and workflow execution commands are separate later actions.
- Delivery is live-only. A command committed while no connected Web client observes its mux frame remains in history but is not replayed into Canvas after reconnect.
- `canvas:command-result` is transient and is not appended to the Session log or returned to the model. Durable execution state, retry policy, and user-facing failure presentation are deferred.
- The active-target path can create a prompt + generator pair, but it does not choose a Canvas provider when none is configured; Infinite Canvas keeps that responsibility and may reject execution.
