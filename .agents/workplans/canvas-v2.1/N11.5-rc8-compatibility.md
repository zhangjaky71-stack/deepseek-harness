## 1. 节点目标

在不破坏既有 Canvas 产品要求的前提下，将私有仓库迁移到 Harness rc.8 的动态 Web Client 架构，并把 Canvas 收敛为正式的 Harness Client Plugin Domain，为 N12 及后续执行链提供稳定基线。

本节点必须同时证明两件不同的事：

1. **Canvas compatibility overlay**：Canvas 已遵守 rc.8 的 slot/store/hook/export/plugin ownership。
2. **Repository final-tree sync**：私有仓库的 Web boot、renderer owner、package/version graph 等已机械对齐官方 rc.8 final tree。

只有第 1 项成立不能完成 N11.5；两项都成立并经过 REAL composition 才能作为 N12 的 accepted baseline。

## 2. 前置依赖

`N11`

N01-N11 已形成的 Canvas Domain、Session durable authority、Remote、UI 状态机和编辑器语义继续有效；本节点只调整/核验 Harness integration ownership，不重写这些业务语义。

## 4. 本节点范围

### Compatibility overlay 范围

- 对齐 rc.8 dynamic client plugin export discipline。
- 对齐 slot/store/hooks/lifecycle ownership。
- Canvas 通过 generic `shell.main` 进入应用。
- Conversation/Composer ownership 保持独立。
- Canvas local state 支持 session prune + plugin dispose/HMR cleanup。
- Host Node Catalog / Settings / Session Projection 继续作为 authority。
- `canvas/change` 保持 required/non-ignorable durable event。
- 建立 built-client / roster / ownership regression gate。

### Full sync 范围（当前阻塞项）

- 官方 rc.8 final package/version tree mechanical sync。
- 引入/对齐 official `packages/client/ui-renderer`。
- 将 React application mount ownership 从 private `packages/client/web` 迁给 dynamic `uiRenderer`。
- 移除 private shell-own `AppRoot` / `APP_SHELL_ID` final-application mount responsibility，按官方 boot ownership 重叠加私有产品 overlay。
- 对齐相关 module/bootstrap/build/tsconfig/lock graph。
- REAL assembled boot + HMR/dispose 验证。

## 5. 明确不在本节点处理

- 不实现 N12 DAG execution。
- 不接真实图片/视频 Provider。
- 不把 Infinite Canvas Python/FastAPI 运行时并入 Harness Node 进程。
- 不通过给 Web boot 增加 Canvas 特判来绕过 rc.8 ownership。
- 不把 Canvas Domain state 放进 `ui-layout` 或 Web boot kernel。
- 不把 compatibility commit 冒充 official-tree post-sync commit。

## 6. 目标架构

```text
Harness framework-free Web Boot Kernel
        │
        ▼
Dynamic Client Plugin Graph
        │
        ├─ runtime / locale / theme / settings
        ├─ ui-renderer           ← React root + uiRenderer.mount owner
        ├─ ui-layout             ← generic layout owner only
        ├─ ui-conversation       ← conversation/composer owner
        ├─ ui-attachment         ← attachment presentation owner
        └─ ui-canvas             ← Canvas UI/domain bridge owner
                 │
                 ├─ shell.main contribution
                 ├─ Minimal / Editor presentation state
                 ├─ Canvas Session Projection
                 └─ Interaction Context preparation
```

关键 ownership：

- Web boot 只负责 module/loader/boot page 与 `uiRenderer` handoff。
- `ui-renderer` 负责 React root。
- `ui-layout` 负责 generic regions。
- `ui-canvas` 负责 Canvas product surface。
- `ui-conversation` 负责 Conversation/Composer。

旧计划中的“Canvas 保留 `conversation.view` slot 接入”已被 N07/N11 架构替代，不能在 N11.5 回退。当前正确 seam 是 `shell.main`。

## 7. 迁移规则

1. 以官方 rc.8 final tree 为 sync target，不用 selective backport 伪装完整同步。
2. 私有 Canvas 定制以 overlay 重新叠加到公开 slot/service seam。
3. 官方文件与私有定制冲突时：先保留官方 lifecycle/API ownership，再重新映射产品需求。
4. `packages/client/ui-layout` 只允许 generic layout seam，不得成为 Canvas owner。
5. `packages/client/web` / `ui-renderer` 不允许出现 Canvas 特判。
6. Browser-only state 必须 session scoped 且支持 dispose/HMR；durable state 只来自 Session Projection。
7. Node Registry metadata 必须由 Host authority 提供，Browser 不维护第二份静态真源。
8. compatibility overlay 与 full-tree sync 必须分别记录 evidence/status。
9. upstream 新增 owner package 缺失时，不允许用旧 owner 的兼容实现把 sync status 标完成。

- 禁止把官方动态 plugin/renderer 重新静态 bundle 回 shell。
- 禁止在未运行 REAL composition 时声称 rc.8 迁移完成。
- 禁止手工编辑 lock/generated artifacts 制造 package-graph 完成假象。
