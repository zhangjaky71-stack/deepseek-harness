# N11.5 — Harness rc.8 compatibility and upstream baseline

Status: `BLOCKED / REVIEW`

## Goal

Prevent Canvas V2.2 from building on a false upstream baseline.

N11.5 has two distinct responsibilities:

1. make the Canvas/private Client overlay obey the rc.8 public ownership/lifecycle contracts it depends on;
2. prove whether the repository as a whole is mechanically synchronized to the official rc.8 release.

Those responsibilities must not share a completion label.

Official target:

```text
deepseek-ai/deepseek-harness
141eb6fef83422698aef7a981029e843e8161534
dsh@0.1.0-rc.8
```

## Current conclusion

The major rc.8 Client lifecycle gaps discovered by the initial audit are now remediated in source:

- dynamic `@deepseek-ai/dsh-client-ui-renderer` owns React root creation/hydration;
- Web boot is framework-free and hands the mount point to `ctx.uiRenderer.mount(container)`;
- Host installs the queue-mode `window.__ModuleLoader__` facade;
- client-modules/runtime are parser-preloaded before Web boot;
- Web creates the module system through the facade;
- the old `window.__DSH_MODULES__`, AppRoot/app-shell and shell-static modules bootstrap are removed.

However, the repository is still **not** accepted as the official rc.8 final tree because release/package/build/tool-owned-output/REAL-CI evidence remains incomplete.

## Compatibility invariants

### Canvas surface ownership

- Canvas product surface: generic `shell.main` contribution.
- Conversation/Composer ownership: Conversation domain, independently rendered.
- `ui-layout`: generic regions only; no Canvas import or business state.
- No `conversation.view` ownership assumption.
- No second Composer owned by Canvas.

### Dynamic client package boundary

`@deepseek-ai/dsh-client-ui-canvas/client` runtime exports stay limited to:

```text
apply
inject
```

Components, stores and helpers are internal implementation details.

### State/lifecycle ownership

- Mode and semantic selection: stable browser-local observables because prompt preparation consumes the same values.
- Render receives those sources through slot `hooks`.
- Editor Draft/save/Undo/Redo/Clipboard/transient positions: presentation-only local/store state.
- Workflow/Run/Asset semantic truth: Session events + Projection.
- Harness Settings, effective capabilities and Media Node Registry: external Host/framework authorities.

## Private compatibility retained intentionally

The private Client build system still has a broader static `PLATFORM_MODULES` / bundle-external baseline than official rc.8 final-tree partitioning.

N11.5 does not rewrite that wider build system speculatively. The retained private baseline already answers currently emitted package requires, while parser-preloaded modules/runtime now provide the rc.8 bootstrap lifecycle.

A later full release sync must audit this partition with the repository toolchain across all client packages.

## CI infrastructure blocker

The stacked Canvas PRs repeatedly show jobs failing before any command executes (`steps=[]` / `steps=null`, log retrieval `BlobNotFound`) or remaining queued on the enterprise runner. A red check with no executed steps is not a Canvas regression, but it is also not validation.

No node is accepted from source inspection alone.

## N12 dependency rule

N12 may be **audited and prepared** while N11.5 remains blocked. It must not claim an accepted rc.8 final-tree baseline, and N11.5 must not be marked accepted, until the full-sync gates above are satisfied.

This allows useful forward engineering without weakening the release boundary.

1. the Canvas/private Client compatibility overlay is mechanically compatible with the rc.8 contracts it consumes; and
2. repository-wide rc.8 release synchronization has toolchain-generated and REAL runtime evidence.

Condition 1 is now substantially implemented in source. Condition 2 is still open.
