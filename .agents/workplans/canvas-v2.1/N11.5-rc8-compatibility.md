# N11.5 — Harness rc.8 Compatibility、Dynamic Client Plugin 与 Canvas Integration Migration

> 项目：`zhangjaky71-stack/deepseek-harness`  
> 文档版本：Canvas V2.2 / Harness rc.8 Compatibility Revision  
> 上游目标：`deepseek-ai/deepseek-harness@141eb6fef83422698aef7a981029e843e8161534` (`dsh@0.1.0-rc.8`)  
> 文档性质：工程实施节点文档  
> 状态原则：在私有仓库完成官方 rc.8 机械同步、兼容修复和 REAL composition 验证前，本节点保持 `BLOCKED/IMPLEMENTING`，不得把“静态兼容审计”误记为“已完成上游升级”。

## 1. 节点目标

在不破坏既有 Canvas 产品要求的前提下，把私有仓库迁移到 Harness rc.8 的动态 Web Client 架构，并把 Canvas 从“页面内定制”收敛成正式的 Harness Client Plugin Domain，为 N12 及后续执行链提供稳定基线。

## 2. 前置依赖

`N11`

N01-N11 已形成的 Canvas Domain、Session durable authority、Remote、UI 状态机和编辑器语义继续有效；本节点只调整 Harness integration ownership，不重写这些业务语义。

## 3. 本节点范围

- 完整同步官方 rc.8 最终文件状态，并记录 upstream SHA。
- 对齐 rc.8 `render-service` 动态 React root ownership。
- 对齐 rc.8 `ui-attachment` 动态插件 ownership。
- 对齐 rc.8 `ui-settings` / schema ownership。
- 保留 Canvas `conversation.view` slot 接入与会话 Composer。
- 保留现有三栏产品拓扑：workspace/sidebar + Canvas + conversation/details overlay。
- 把 Minimal/Editor、selection、Canvas session binding 等状态归属收敛到 `ui-canvas/canvas-runtime`，不得归属 `AppFrame`。
- 验证 `canvas/change` Session event 在 rc.8 下仍是 required/non-ignorable 的 durable Canvas 事件。
- 建立 REAL assembled boot / dynamic plugin lifecycle 回归门禁。
- 建立后续 rc.9+ 升级所需的 upstream baseline 与 compatibility policy。

## 4. 明确不在本节点处理

- 不实现 N12 DAG execution。
- 不接真实图片/视频 Provider。
- 不把 Infinite Canvas Python/FastAPI 运行时并入 Harness Node 进程。
- 不通过修改 `render-service` 私有实现来硬编码 Canvas。
- 不把 Canvas Domain state 放进 `ui-layout` 或 Web boot kernel。

## 5. 目标架构

```text
Harness Web Boot Kernel
        │
        ▼
Dynamic Client Plugin Graph
        │
        ├─ runtime / locale / theme / settings
        ├─ render-service        ← React root owner
        ├─ ui-layout             ← layout owner only
        ├─ ui-conversation       ← conversation/composer owner
        ├─ ui-attachment         ← attachment presentation owner
        └─ ui-canvas             ← Canvas UI/domain bridge owner
                 │
                 ├─ conversation.view slot
                 ├─ Minimal / Editor view state
                 ├─ Canvas session projection
                 └─ Interaction Context
```

`render-service` 负责应用挂载；`ui-layout` 负责布局；`ui-canvas` 负责 Canvas 能力。三者不得互相吞并职责。

## 6. 迁移规则

1. 以官方 rc.8 final tree 为基础，不挑选性 cherry-pick 代替完整同步。
2. 私有定制以 overlay 方式重新叠加，优先迁移到独立 Canvas package/plugin。
3. 若官方文件与私有定制冲突：优先保留官方 lifecycle/API，再把产品需求重新映射到公开 slot/service seam。
4. `packages/client/ui-layout` 允许保留最小布局 seam，但不得成为 Canvas Domain owner。
5. `packages/client/web` / `render-service` 不允许出现 Canvas 特判。
6. 任何 Browser-only state 必须 session scoped 且支持 dispose/HMR；durable state 仍只来自 Session Projection。
7. 任何 plugin catalog/Node Registry metadata 必须由 Host authority 提供，Browser 不维护第二份静态真源。

## 7. 实施步骤

1. 锁定 rc.8 upstream SHA 与私有 pre-sync SHA。
2. 完成完整 upstream tree 同步。
3. 逐项分类冲突：boot/render/layout/attachment/settings/session/client plugin。
4. 把 Canvas 集成迁移到动态 client graph，不在 Web shell 创建静态 Canvas root。
5. 恢复并验证三栏布局、conversation details overlay、Minimal/Editor。
6. 验证 ui-canvas 的 activation/dispose/HMR 行为。
7. 验证 image attachment intake 与 Canvas AssetRef 路径不复制 base64。
8. 验证 Canvas Session event / projection / reconnect。
9. 更新 workspace/build/knip/tsconfig/README 等 rc.8 新 package graph 所需配置。
10. 运行 REAL assembled client test，并记录证据。

## 11. 风险与禁止项

- 禁止用 iframe/AppFrame 临时接法替代最终 plugin architecture，然后把临时状态标为完成。
- 禁止为了降低冲突直接保留 rc.7 Web shell。
- 禁止把官方动态插件重新静态 bundle 回 shell。
- 禁止在未运行 REAL composition 时声称 rc.8 迁移完成。
