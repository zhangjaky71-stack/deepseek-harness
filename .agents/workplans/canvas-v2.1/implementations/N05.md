## What changed in this re-review

The earlier N05 implementation was not sufficient for the V2.2/N04 authority model. In particular it could leave stale browser values after an ACL/HMR visibility change, treated malformed Canvas projection events as fail-soft, identified layouts only by workflow id, had no independent layout CAS revision, and did not carry exact persisted Session identity through every cold/detached browser-read path.

The re-review and repository validation found additional edge cases that were not visible in the first pass:

1. HMR replacement cannot safely mean “same key implies same owner”; otherwise an unrelated plugin can shadow another domain's Projection. Explicit stable owner identity is required for replacement.
2. History source identity can change while the core ApiProxy awaits presenter composition. Admission-time live/detached classification is insufficient; the final returned tail cut must be re-secured against an exact source after the core response exists.
3. If a live Session exists but has already advanced past the transcript cut being returned, that live mismatch must not suppress a persisted source that still exactly represents the returned cut. The final-source decorator now falls through from a non-matching live source to persisted inspection.
4. Projection-cache lifecycle identity cannot be just `createdAt + cwd`. Two distinct lifecycles can share those values, so cache rows are now bound to the immutable Session-header identity fields and the cache domain version is bumped.
5. A successful layout mutation receipt can advance the Browser CAS token before the corresponding Projection arrives. A delayed older Projection must not roll that token backwards, and a late receipt from an old Canvas/workflow generation must not contaminate the new generation. The Editor now uses a generation-scoped monotonic layout-revision clock.

This repair changes those contracts rather than documenting the old behavior as acceptable.

## Delivered — Projection authority

- `SessionProjectionMap.canvas` remains the current `CanvasSnapshot | null`; `canvasLayout` is the current generation's `CurrentCanvasLayoutSnapshot | null`.
- Canvas projection mathematics remains synchronous and Session-log-derived. Unrelated events retain same-reference fast paths, but malformed own-domain `canvas/change` / `canvas/layout-change` candidates fail loud rather than silently preserving a stale current value.
- Browser read guards remain outside fold mathematics and checkpoint state. Denial removes only browser visibility; the Host retains complete rebuildable projection state.
- `viewCheckpoint()` and `restore()` accept an explicit browser `ProjectionReadContext`, allowing a trusted carrier to supply the target persisted Session identity without inventing a live Session object.
- Live `snapshot(session)` and change delivery use exact `Session.id`.

## Delivered — same-seq visibility ordering

A Session durable seq cannot represent an ACL, HMR or capability transition that happens without another Session event. The registry therefore maintains per-Session/per-key monotonic browser visibility generations.

- Live change frames may carry a reserved framework control envelope in the existing `value` slot.
- `present:false` explicitly revokes a Browser key at the current durable seq.
- `present:true` can restore the current whole value at the same durable seq.
- Client `ProjectionValueStore` orders those transitions by `(seq, visibilityGeneration)` and drops stale generations.
- Ordinary domain value frames retain durable-seq ordering after a baseline has established visibility.
- Fresh baselines can re-establish authority after reconnect/truncation.
- Empty-log visibility frames use the same `-1` watermark used by `ProjectionSnapshot.asOfSeq` and `session/subscribed.lastSeq`; the wire schema accepts it.
- The control envelope is not part of `SessionProjectionMap`; the `/types` outlet remains runtime-free.

`visibilityGeneration` is transport/read-visibility ordering only. It is deliberately **not** a Canvas domain revision.

## Delivered — projection HMR/disposal

The initial repair used latest-definition-active semantics for any overlapping key. The final contract is stricter:

- `ProjectionDefinition` can declare a stable `owner`.
- Same-key + same explicit owner uses latest-live-definition HMR replacement.
- The replacement rebuilds cells from authoritative Session history and can republish current values at the same durable seq through a visibility generation.
- Late disposal of the old same-owner registration cannot roll back the replacement.
- Different owners claiming the same key fail loud.
- Legacy unowned duplicates retain same-`stateVersion` first-live compatibility semantics rather than being treated as HMR identity.
- If the active unowned registration unloads first, the registry promotes the next surviving definition and rebuilds cells; it never retains a disposed ghost definition.
- Disposing the last registration publishes explicit absence for known sessions.

Canvas explicitly owns its two keys through stable owners:

```text
@deepseek-ai/dsh-canvas:canvas
@deepseek-ai/dsh-canvas:canvasLayout
```

Focused HMR coverage includes same-owner overlap, old-fiber-late-disposal, different-owner collision, legacy co-registration, and active-legacy-first-disposal.

## Delivered — exact identity on live/cold/history carriers

The Browser read-authorization boundary receives the real target Session identity on all implemented projection carrier paths:

| Path | Identity supplied to read guard |
|---|---|
| live registry snapshot/change | live `Session.id` |
| history tail after final source check | matching live `Session.id`, otherwise request target persisted `SessionId` |
| subagent history tail | matching live child `Session.id`, otherwise persisted child `SessionId` |
| cold `session.list` projection cache | listed `SessionHeader.id` |
| cold projection restore/tail replay | requested persisted `SessionId` |

`packages/host/apiproxy/src/projection-aware-api-proxy.ts` decorates **every successful tail history response**, independent of whether the Session looked attached or detached at method admission. After the core gateway has mounted presenter/preset composition and produced its transcript page, the decorator:

1. reads the page-end seq;
2. if a live Session currently exists and its log-end matches that page-end, recomputes with `registry.snapshot(live)` so guards receive exact live `Session.id`;
3. if live is absent **or does not represent that exact cut**, inspects the persisted target and requires its log-end to equal the same page-end before exact-identity `registry.restore()`;
4. if no exact matching source exists, or recomputation throws, removes the entire `projections` block while leaving the transcript response intact.

This closes detached→live, live→detached, and live-ahead/persisted-exact timing windows around the core handler's awaits. A generic core baseline evaluated without exact target identity is never used as fallback.

`SessionProjectionCache.cachedSnapshot()` and `coldSnapshot()` pass exact identity into checkpoint/restore guards. The cache record is also bound to the immutable Session-header lifecycle identity:

```text
version + createdAt + cwd + parentSession + seedLength + origin + delegationDepth + agentPreset
```

The cache domain is version `4`; incompatible earlier cache media is rebuildable and discarded rather than migrated into false authority. Regression coverage proves different lineage/preset identities are rejected even when `createdAt` and `cwd` match.

A persisted checkpoint remains a performance shortcut; it cannot bypass N04 read authorization or seed state from another Session lifecycle.

## Delivered — independent Layout authority

Current layout is identified by three presentation fields:

```text
canvasId + workflowId + layoutRevision
```

while semantic/run revisions remain separate:

```text
workflowRevision
runRevision
layoutRevision
```

Key changes:

- Added `CurrentCanvasLayoutSnapshot` with `canvasId` and `layoutRevision` while retaining historical layout decoding compatibility.
- Strict layout replay follows `canvas/change` and `canvas/layout-change` together so create/clear changes the active layout generation.
- Historical pre-current-field layout rows are normalized only while replaying their containing Canvas generation.
- Current writers carry the exact current Canvas generation and a contiguous independent `layoutRevision`.
- `SaveCanvasLayoutRequest` carries `canvasId`, `workflowId`, and `expectedLayoutRevision`.
- `CanvasService.saveLayout()` independently enforces Canvas identity, workflow identity, revision CAS, current node membership, Host authorization and write authority before Session append.
- Successful mutation receipts return the new `layoutRevision`.
- A stale tab cannot overwrite another tab's newer layout.
- Clearing and recreating a Canvas with the same workflow id cannot resurrect the old Canvas's layout.
- Layout writes do not increment `workflowRevision` or `runRevision`.

## Delivered — Browser editor fencing and absence presentation

- `WorkflowEditor` applies projected layout only when both `layout.canvasId === canvas.id` and `layout.workflowId === canvas.workflow.id`.
- Browser layout CAS state is generation-scoped by `canvasId + workflowId`.
- Within one generation, projected revisions and successful Host receipts can only advance the local CAS token monotonically; an older delayed Projection cannot roll it backwards.
- A late mutation receipt from a previous Canvas/workflow generation is ignored rather than advancing the new generation's token.
- stale layout revision and stale Canvas generation surface as `conflict`, not as an ordinary save failure.
- Browser consumes `canvas` / `canvasLayout` through Session Projection and does not replay Canvas Session events itself.
- `useProjection('canvas') === undefined` is not rendered as perpetual “syncing”. `CanvasView` combines it with authoritative Session `openState`: `cold/loading` means baseline pending, while `open/error` means the key is currently unavailable/hidden. The unavailable copy is intentionally generic and does not reveal ACL policy details.

## Documentation corrections

The old implementation record described malformed projection events as fail-soft and implied detached reads necessarily had no Session identity. Those statements are no longer valid. Carrier-owned persisted identity is explicit where available, while the projection fold itself stays identity-free.

The final re-review also replaces overly broad statements:

- “latest definition wins for the same key” is now “latest definition wins only for the same explicit owner; different owner collisions fail loud; unowned duplicates are compatibility-only first-live semantics”.
- “a detached race degrades to the core response” is now “a final-source or cut mismatch removes the entire projection block; a generic core baseline is never a security fallback”.
- “live source wins” is now “live source wins only when it represents the exact returned cut; otherwise persisted exact-cut verification is still attempted”.
- “layout receipt immediately advances the token” is now explicitly generation-scoped and monotonic relative to Projection delivery.
