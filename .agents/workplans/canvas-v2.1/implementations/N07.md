## Architecture decisions

### Product surface ownership

```text
render-service = React root owner
ui-layout      = generic shell region/layout owner
ui-conversation= Conversation/Composer owner -> shell.right
ui-canvas      = Canvas product owner         -> shell.main
```

`conversation.view` remains an internal Conversation composition seam. Using it as the Canvas product surface would couple two separate product owners and make Composer/body behavior depend on registration order. N07 therefore uses `shell.main` as the neutral central product region while keeping `ui-layout` semantically unaware of Canvas.

### Projection and local state

Canvas current state remains Session Projection-owned. Minimal/Editor mode and interaction selection are presentation-only browser state. They may survive view remounts within the plugin lifetime, are pruned when Sessions leave the client catalog, and are cleared when the plugin is disposed/replaced.

### Dynamic capabilities

`remote.canvasFeatures` is the deployment gate. Canvas publishes no main surface when `canvas.enabled=false` or feature discovery fails. Once Canvas is enabled, Editor catalog failure degrades to a readable Minimal surface and `remote.canvas` mutation availability is optional for rendering. This keeps read availability separate from write availability without inventing a second capability authority.
