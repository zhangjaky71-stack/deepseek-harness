# N04 Implementation — Host authorization, provenance, audit, and durable-data security

Status: REVIEW  
Date: 2026-08-21  
Branch: `fix/canvas-n04-v2.2-host-security`  
Base: `fix/canvas-n03-v2.2-durable-authority`

## Remediation delivered

### Host authorization contract

- Retained the shared `CanvasPermission` vocabulary and added typed `CanvasAuthorizationResource` scope for session/canvas/workflow/run/asset/variant/layout policy decisions.
- Added `CanvasServiceConfig.authorizationMode` with `single-user-fallback` and fail-closed `required-external` modes.
- External authorization exceptions are normalized to a policy-unavailable decision; CanvasService exposes `CANVAS_AUTHORIZATION_FAILED` rather than raw policy/identity-provider diagnostics.
- Ordinary denies remain generic `CANVAS_PERMISSION_DENIED`; policy-specific internal codes are not Browser authorization oracles.

### Actor/source provenance

- `CanvasAccessContext` is canonicalized and then bound to the actual Host target Agent/Session.
- Browser Remote must be `human` with the Host Session surrogate identity; Agent Tool must be `agent` with the exact target Agent id; reconciler must be `system`; direct Host calls use the exact Agent or a system actor.
- Added Host-owned access factories for Host Agent, Browser, Agent Tool, and system/reconciler callers.
- Durable actor/request/correlation identifiers are bounded; request/correlation ids are log-safe and reject control characters/outer whitespace.

### Current durable writer authority

- Added process-local one-shot Canvas write permits for current `canvas/change` and `canvas/layout-change` appends.
- CanvasService acquires the permit only after authorization/provenance/domain/audit/preflight validation.
- The Canvas Session precommit invariant consumes the exact permit. A structurally valid current event appended directly by another Host path is rejected before Session publication.
- Historical late-load replay is not permit-gated, preserving stored compatibility.

### Durable sensitive-data boundary

- Expanded workflow scanning beyond the old finite key set: normalized/suffixed API-key/token/secret/header/binary carriers are rejected, plus explicit data-URL base64, PEM private-key, Bearer credential, and common long `sk-`/`rk-` signatures.
- Preserved ordinary semantic fields such as `maxTokens` / `tokenLimit`; the implementation does not use a broad `includes('token')` rule.
- Added `assertCanvasDurableAuditSafe()` so current Run error code/message and safe asset display metadata are checked in addition to workflow node config.
- Provider/raw HTTP errors are therefore required to be classified/redacted before they can become durable `CanvasRunError` values.
- The documented threat model distinguishes Host/Provider structural credential exclusion from impossible-to-guarantee DLP over arbitrary user-authored natural-language text.

### Browser Projection read security

- Added generic browser-facing read guards to `SessionProjectionRegistry` without changing pure projection fold mathematics.
- Guards compose with AND semantics, fail closed on throw, and dispose with the registering fiber.
- Live snapshot/change-feed guards receive the exact Session id; detached checkpoint/restore browser views receive no invented identity.
- Canvas registers the same `canvas.read` Host decision over both `canvas` and `canvasLayout`, closing the prior gap where `ctx.canvas.get()` could be denied while Session Projection still exposed current Canvas state.
- Internal projection cells/checkpoints retain complete derived state; authorization is visibility filtering, not durable deletion.

## Tests added/updated in source

Canvas security tests now cover:

- human read allow / edit deny;
- agent run allow / human run deny with typed resource scope;
- dedicated initial variant permission;
- provenance spoofing across Browser/Agent Tool/Reconciler sources;
- CanvasService writes while the invariant companion is mounted;
- metadata v1 decode compatibility + current metadata v2 writer behavior;
- audit allow-listing;
- `X-API-Key`, data-URL base64, Bearer credential, and PEM rejection;
- non-secret `maxTokens/tokenLimit` false-positive regression;
- unsafe Provider diagnostic rejection;
- bounded request id rejection;
- fail-closed `required-external` mode;
- `canvas.read` denial on Browser Projection delivery.

Canvas invariant tests now treat direct current Canvas/Layout append as an authority violation, while historical seed replay remains supported.

Session Projection read-guard tests cover deny filtering, change-feed suppression, throw→deny, live Session identity, detached identity absence, disposal/HMR behavior, and AND composition.

## Security boundary deliberately deferred

N04 does not implement:

- authenticated multi-user human identity or tenant/workspace ACL;
- N15 quota/cost/admission policy;
- N16/N22 Job/provider callback lifecycle sources;
- N23 full telemetry/log redaction pipeline;
- general-purpose DLP for secrets deliberately pasted into arbitrary user prompt text.

Those capabilities must reuse this Host seam rather than create parallel authorization or audit systems.
