# N04 Implementation — Authorization, actor, audit, and sensitive-data boundary

Status: REVIEW  
Date: 2026-08-19  
Branch: `agent/canvas-n04-authorization-audit`  
Base: `agent/canvas-n03-event-sourcing-service`

## Delivered

- Added the shared `CanvasPermission` action vocabulary for current and future CanvasService, Remote, Agent Tool, History, Asset, restore, variant, and layout consumers.
- Added explicit `CanvasActor`, `CanvasRequestSource`, `CanvasAccessContext`, authorization request/decision DTOs, and stable service errors for permission denial, invalid access context, and sensitive durable data.
- Added `CanvasAuthorizationPolicy`, an actor-kind allow-list policy with per-permission overrides and a current single-user allow-all default.
- Added optional Cordis `CanvasAuthorizationService` as `ctx.canvasAuthorization`; `CanvasService` uses it through `ctx.get()` when mounted and otherwise uses the same policy implementation as its fallback.
- Routed CanvasService current reads and all N03 business mutations through Host authorization before any new Session append.
- Added independent `canvas/change.meta` schema version 2 with canonical actor/source plus optional request/correlation ids; historical metadata schema version 1 remains readable without inventing actors for old events.
- Added allow-list audit materialization so arbitrary caller properties are discarded rather than serialized into Session.
- Added pre-commit semantic workflow scanning for credential/header/binary-shaped keys; rejections do not echo the rejected value.
- Kept authorization decisions out of durable state: accepted mutations plus actor/source attribution remain the durable facts.

## Validation completed

- Strict TypeScript structural checks were completed for the authorization/audit source changes using `strict`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes`.
- Authorization tests cover human read allow / edit deny, agent run allow / human run deny, system reconciler audit attribution, historical metadata v1 decoding, metadata allow-listing, and sensitive workflow rejection before append.
- Static commit-boundary review confirms authorization and sensitive-data validation occur before the mutation's `session.append('canvas/change', ...)` call.
- N04 does not add Browser Remote, Projection, provider execution, Agent Tool, History implementation, Asset routes, or UI; it only establishes the Host seam they must consume.
