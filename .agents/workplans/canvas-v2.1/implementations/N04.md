# N04 Implementation — Host authorization, provenance, audit, and durable-data security

Base: `fix/canvas-n03-v2.2-durable-authority`

## Remediation delivered

### Host authorization contract

- Retained the shared `CanvasPermission` vocabulary and added typed `CanvasAuthorizationResource` scope for session/canvas/workflow/run/asset/variant/layout decisions.
- Added `CanvasServiceConfig.authorizationMode` with `single-user-fallback` and fail-closed `required-external` modes. Unknown runtime values are rejected instead of silently becoming the permissive fallback.
- Missing external authorization in required mode, external exceptions, malformed/contradictory external decision shapes, and unsupported decision fields all normalize to policy-unavailable; CanvasService exposes `CANVAS_AUTHORIZATION_FAILED` instead of raw policy/identity backend diagnostics.
- External allow decisions are accepted only as exact `{ allowed: true }`; denied decisions accept only the declared contract fields, with bounded log-safe `policyCode` when present.
- Ordinary denies remain generic `CANVAS_PERMISSION_DENIED`; policy-specific internal details are not Browser authorization oracles.
- Initial `currentVariantId` admission now generates the candidate Canvas id first and authorizes `canvas.variant.create` against an explicit `{ kind: 'variant', canvasId, variantId }` resource rather than falling back to a Session-only scope.

### Actor/source provenance

- `CanvasAccessContext` is canonicalized and bound by Host-owned source rules before CanvasService authorization/commit.
- Browser Remote and Asset Route use one Host-minted single-user Browser principal, `human:host-browser`. The target Session is carried separately in `CanvasAuthorizationRequest.sessionId`/resource and is never promoted into a human identity.
- Agent Tool must use `agent` with the exact target Agent id; reconciler must use `system`; direct Host calls use the exact Agent or a system actor.
- Host-owned access factories cover Host Agent, Browser, Agent Tool, and system/reconciler callers. `canvasBrowserAccess()` requires a resolved Session target but returns the stable Host Browser principal.
- Interaction Bridge consumes the same Browser factory; its regression fixture deliberately uses different Agent and Session ids so the security contract does not depend on identity equality.
- Durable actor/request/correlation identifiers are bounded; request/correlation ids are log-safe and reject control characters/outer whitespace.

### Current durable writer authority

- Added process-local one-shot Canvas write permits for current `canvas/change` and `canvas/layout-change` appends.
- CanvasService acquires the permit only after authorization/provenance/domain/audit/preflight validation.
- When the Canvas invariant companion is mounted, Session precommit consumes the exact permit. A structurally valid current event appended directly by another Host path is rejected before publication.
- Historical late-load replay is not permit-gated. Lightweight compositions without the invariant companion still rely on CanvasService correctness; production mechanical direct-append rejection therefore has an explicit composition requirement.

### Durable sensitive-data boundary

- Expanded workflow scanning beyond the old finite key set: normalized/suffixed API-key/token/secret/header/binary carriers are rejected, plus explicit data-URL base64, PEM private-key, Bearer credential, and common long `sk-`/`rk-` signatures.
- Preserved ordinary semantic fields such as `maxTokens` / `tokenLimit`; the implementation does not use a broad `includes('token')` rule.
- Added `assertCanvasDurableAuditSafe()` so current Run error code/message, image/video durable object ids, media type, and safe image display metadata are checked in addition to workflow node config.
- Image `attachmentId` and video `assetId` must remain opaque storage ids; URL-shaped references are rejected so bearer/signed provider URLs cannot become Session authority. The shipped local attachment backend uses `sha256:<64hex>`, which remains valid because the URL check only rejects `scheme://...` forms.
- Provider/raw HTTP errors must therefore be classified/redacted before becoming durable `CanvasRunError` values.
- The threat model distinguishes Host/Provider structural credential exclusion from impossible-to-guarantee DLP over arbitrary user-authored natural-language text.

### Browser Projection read security

- Added generic Browser-facing read guards to `SessionProjectionRegistry` without changing pure projection fold mathematics.
- Guards compose with AND semantics, fail closed on throw, and use Cordis traceable service rebinding so their `ctx.effect()` ownership follows the caller fiber.
- Live snapshot/change-feed guards receive the exact target Session id; detached checkpoint/restore Browser views receive no invented Session identity.
- Canvas registers the same `canvas.read` Host decision over both `canvas` and `canvasLayout`. Live decisions use the same Host-minted Browser principal as Remote/Interaction plus the separate Session target.
- A live Projection read now resolves the exact live Session, synchronizes the same Canvas fold cache used by `ctx.canvas`, and derives the same current `CanvasAuthorizationResource` as `ctx.canvas.get()`: `session` only before Canvas creation/after clear, otherwise the concrete `canvas` resource. An external ACL cannot therefore allow Session-level read while denying the current Canvas and still leak that Canvas through Projection.
- Internal projection cells/checkpoints retain complete derived state; authorization is visibility filtering, not durable deletion.
- Projection-cache writes were checked: durable cache persistence uses `checkpoint()`, not the guarded change feed, so read denial does not erase cached derived state.

## Security boundary deliberately deferred

N04 does not implement:

- authenticated multi-user human identity or tenant/workspace ACL;
- a generic detached projection carrier API that supplies an explicit Session target to read guards (identity-dependent Canvas detached reads currently fail closed);
- N15 quota/cost/admission policy;
- N16/N22 Job/provider callback lifecycle sources;
- N23 full telemetry/log redaction pipeline;
- general-purpose DLP for secrets deliberately pasted into arbitrary user prompt text.

Those capabilities must reuse this Host seam rather than create parallel authorization or audit systems.
