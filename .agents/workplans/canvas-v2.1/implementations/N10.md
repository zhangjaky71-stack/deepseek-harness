# N10 Implementation — Media Node Registry, lifecycle metadata, and catalog revision identity

Status: REVIEW  
Date: 2026-08-22

## Stack / remediation context

The historical branch `agent/canvas-n10-node-registry` was audited against the current N09 remediation head and was **194 commits behind / 0 commits ahead**. Its functional work had already been absorbed into the later stack, so it was not a safe continuation base. N10 therefore continues on a clean remediation branch based directly on the accepted-for-review N09 head.

The existing N10 implementation already provided the major registry/open-world/lifecycle work. The remaining architectural gap was narrower but important: the Browser-safe node catalog was exposed only as an array. There was no catalog identity proving which exact Host Registry mutation state produced those entries, so the workplan requirement “Browser catalog 与 Host registry revision 一致” could not be mechanically tested across registration, disposal, or HMR replacement.

This remediation adds that missing revision identity without creating a second Browser registry or changing Canvas durable state.

## Delivered registry authority

- `@deepseek-ai/dsh-media-workflow` remains the process-local semantic node-definition registry shared by later Validator, Editor, Agent-summary, and Executor consumers.
- `ctx.mediaNodes` keeps effect-scoped `(type, version)` registration, exact duplicate rejection, deterministic lookup/listing, config parsing, creatable/executable lifecycle checks, and registration-change observation.
- Registered definitions remain frozen snapshots except for the defining plugin's Zod schema reference.
- Built-in definitions remain the seven V1 semantic nodes: `asset.input@1`, `prompt@1`, `image.generate@1`, `image.edit@1`, `video.generate@1`, `video.image-to-video@1`, and `output@1`.
- The registry remains open-world. Built-ins are initial registrations, not a permanent Canvas Domain whitelist.

## New mutation revision / atomic snapshot contract

`MediaNodeRegistry` now owns a process-local monotonic mutation revision and exposes:

```ts
snapshot(): MediaNodeRegistrySnapshot
// { revision, definitions }
```

The contract is intentionally exact:

- a new Registry instance starts at revision `0`;
- each successful definition registration advances revision exactly once;
- each successful exact unregistration advances revision exactly once;
- duplicate-registration and definition-validation failures do not advance revision;
- HMR-style unload followed by re-registration is represented by two distinct mutations/revisions;
- `snapshot()` reads the revision and stable ordered definition list synchronously from the same Registry state;
- the revision is process-local/rebuildable metadata, not Canvas/Session durable state and not a cross-restart generation.

`MediaNodeRegistryChange` now includes the resulting mutation revision so observers can relate lifecycle notifications to the same Registry sequence.

## Host → Browser catalog identity

N10 now defines a client-safe `CanvasNodeCatalogSnapshot`:

```ts
interface CanvasNodeCatalogSnapshot {
  revision: number
  entries: readonly CanvasNodeCatalogEntry[]
}
```

`CanvasFeatureService.remoteExportListNodes()` reads `ctx.mediaNodes.snapshot()` and returns the exact Host revision with data-only entries. Runtime Zod schemas/functions, Provider clients, credentials, executors, and mutable Host objects remain Host-only.

The Browser `ui-canvas` consumer now keeps `nodeCatalogRevision` alongside the loaded `nodeCatalog`. It never increments or fabricates a local revision. If Editor catalog discovery fails, Editor degrades for that activation, Minimal remains readable, and `nodeCatalogRevision` is absent rather than pretending an empty local catalog has a Host identity.

This is still an activation snapshot, not a second synchronization subsystem. N10 does not add polling or push subscription. A future refresh can call Host again and receives a new exact Registry revision if definitions changed.

## Open-world node-type behavior retained

The earlier N10 correction remains intact:

- `MediaWorkflowNodeType` is declaration-mergeable instead of a permanent seven-type whitelist.
- Canvas durable Domain validation preserves arbitrary plugin node types rather than deleting/rejecting historical values solely because a plugin is not installed now.
- N02 remains strict for known built-in future versions through the built-in version map.
- Missing plugin definitions remain readable as historical Workflow data but fail current Registry/execution use explicitly.
- Installing the matching plugin definition makes the same historical node resolvable without editing a Canvas core switch.

During this remediation we explicitly did **not** add a new built-in node-type regex/whitelist to `MediaNodeRegistry`. Repository rules treat these plugin registrations as typed same-process calls; adding a defensive closed-world admission rule would undermine the extension model without improving the durable trust boundary.

## Lifecycle semantics retained

Intrinsic lifecycle and deployment capability remain separate axes.

- `deprecated=true`, `creatable=false`, `executable=true` can keep historical nodes usable while preventing new authoring.
- `executable=false` remains an intrinsic hard block.
- N09 deployment feature state is not copied into Registry state. Definitions can declare a static feature requirement such as `video`; consumers combine it with `ctx.canvasFeatures` at the use boundary.
- Definition removal/unload changes only current process metadata and the Registry revision. It never appends Canvas events or rewrites historical workflow nodes.

## Validation coverage implemented

Focused source tests now encode the revision contract in addition to the previous N10 coverage:

- duplicate registration leaves the original definition intact and does **not** advance revision after the failed attempt;
- Registry starts at revision `0`;
- plugin registration → `1`, disposal/unregister → `2`, HMR-style replacement registration → `3`, replacement disposal → `4`;
- `onChange` emits the exact resulting revisions for register/unregister mutations;
- seven built-in registrations produce revision `7`;
- deprecated/non-creatable-but-executable and intrinsic non-executable behavior remains covered;
- config defaults/validation and all seven built-in definitions/ports/UI metadata remain covered;
- Host feature tests prove `canvasFeatures.listNodes()` returns the exact current Registry revision and reflects a later Registry snapshot on the next call;
- Browser capability-gate tests prove the exact Host revision is retained with the Editor catalog, while catalog failure leaves `nodeCatalogRevision` undefined and preserves Minimal degradation.

Earlier open-world tests remain applicable: `plugin.demo@3` survives durable decode while absent, fails Registry use explicitly, and resolves after plugin registration; built-in future `image.generate@99` still fails loud through N02 migration protection.
