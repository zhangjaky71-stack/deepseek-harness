# N12 Implementation — Media Workflow Engine v2.2

## Status

`REVIEW`

N12 source, focused tests, package documentation, and published-path smoke coverage are implemented on `fix/canvas-n12-v2.2-workflow-engine`. The node is not marked accepted because repository-pinned CI has not yet produced a trustworthy exact-head execution result; the existing Canvas stack is currently affected by GitHub Actions jobs that fail before steps start or remain queued on unavailable runners.

## Scope and baseline

N12 is stacked on `fix/canvas-n11-5-v2.2-rc8-renderer-root` / PR #41. It extends `@deepseek-ai/dsh-media-workflow` from the N10 versioned Definition Registry into a Browser-independent DAG validation/planning/execution library.

Historical branches were audited before implementation:

- `agent/canvas-n12-workflow-engine`: behind 290, ahead 5 relative to the current N11.5 remediation head.
- `agent/canvas-n12-workflow-engine-v2`: behind 282, ahead 1.

Neither historical branch was used as the continuation base. The `-v2` implementation was read as design prior art and the final code was rebuilt on a clean remediation branch.

## Ownership decisions

N12 owns only media DAG semantics and execution mechanics:

- static graph/port/config/intrinsic-executability validation;
- deterministic topology and partial execution planning;
- immutable semantic workflow snapshots;
- exact type/version executor dispatch;
- graph-aware execution fingerprints;
- deterministic cache seam;
- optional in-band runtime event sink;
- cancellation signal propagation/checks.

The following remain outside N12:

- N13: model descriptors, requirements, strict/fallback model resolution, and production of the final provider/model execution identity;
- N14: Provider adapters, Provider registry/routing, credential/network operations;
- N15: N09 deployment feature enforcement, authorization, quota/cost/approval/concurrency/idempotency admission;
- N16: durable Canvas Run/Job lifecycle, retry, cancellation ownership, terminal-state races, reconciliation;
- Canvas/Session: durable state and event append;
- Browser/UI: rendering and editor interaction.

The Engine therefore consumes an already-resolved `MediaNodeExecutionIdentity.key`; it does not expose a resolver callback and cannot select a model or Provider itself.

## Historical-v2 issues found and remediated

The historical `agent/canvas-n12-workflow-engine-v2` was useful prior art, but five important issues were not carried forward:

1. **Model ownership was blurred.** Historical `MediaWorkflowRunRequest.resolveModelKey()` let the Engine invoke model resolution during execution. The final N12 request instead accepts a stable caller-provided execution identity. N13 remains the resolver owner.
2. **Fingerprint ordering lost graph identity.** Historical fingerprinting sorted same-port inputs by content fingerprint, which could alias different graph edges/topologies. The final payload includes edge id, source node/port, target port, and content fingerprint, canonically ordered by edge identity.
3. **Cache hits bypassed output validation.** Historical cached results could flow downstream without re-running executor-output checks. The final Engine validates, detaches, and freezes cached results with the same contract used for fresh executor results.
4. **The runtime event seam was only described.** The final implementation has an optional in-band `WorkflowEventSink` with `node-started`, `node-cache-hit`, and `node-completed` facts. It is intentionally non-durable and does not append Session events.
5. **Cancellation was checked too early.** The final Engine checks `AbortSignal` before execution and again after cache/executor async work, so an executor that ignores the signal cannot return a late result that is accepted after cancellation.

## Implementation

### Validation

`src/validate.ts` resolves exact N10 Definitions and validates config schemas, intrinsic `executable` lifecycle, ports, type compatibility, multiplicity, required inputs, outputs, reachability, and cycles. Topological order uses stable node-id tie-breaking and does not depend on caller node/edge array order.

Diagnostics cover malformed structural values as well as execution-specific semantics. Canvas Domain owns its own persisted-value invariants; N12 diagnostics remain useful because the Engine can be called with typed values that were not constructed through a Canvas helper.

### Scheduler / partial execution

`src/scheduler.ts` implements:

- `all`: complete DAG;
- `selected`: selected targets plus necessary upstream closure;
- `from-node`: seed plus descendants, with unscheduled upstream edges exposed as boundaries;
- `downstream`: descendants excluding seed nodes, with seed-produced values supplied through boundaries.

Missing boundary values fail at execution. The Engine never silently schedules an excluded upstream node. Partial scheduling also rejects Definitions with `supportsPartialRun=false`.

### Immutable snapshot

`MediaWorkflowEngine.prepare()` validates the workflow, parses/normalizes each node config through its exact Definition, clones the semantic value, fills the exact node version, and recursively freezes the snapshot. A caller mutating the original workflow after run preparation cannot change execution semantics.

### Executor dispatch

`src/executor.ts` provides an exact `(type, version)` `MediaNodeExecutorRegistry`, registration disposal, and shared output validation. There is no giant node switch. A custom Definition plus exact-version Executor participates without modifying Engine code.

The Registry is intentionally a pure process-local object in N12. No new shipped Cordis service row was added without a current owner/consumer. N14 can adapt/mount provider-backed registration when that layer exists.

### Fingerprint and cache

`src/fingerprint.ts` computes SHA-256 over canonical data including:

- exact node type/version;
- normalized config;
- optional already-resolved execution identity key;
- edge/source/target identity;
- upstream/content fingerprints.

Automatic cache reuse occurs only for Definitions declaring `deterministic=true`. `MemoryMediaNodeExecutionCache` detaches values on read/write. Cache hits are still run through output validation and immutable snapshotting before downstream use.

### Runtime event and cancellation seams

The optional `WorkflowEventSink` publishes in-band runtime facts. Sink rejection fails the current Engine call; the Engine does not persist those facts. N16 owns any durable mapping.

The same caller-provided `AbortSignal` is passed to Executors and checked at engine-controlled settlement points, including after executor completion.

## Validation evidence and blocker

Static review confirms the branch is built from the N11.5 remediation head and the implementation is confined to `packages/canvas/media-workflow/**` plus N12 documentation/Agent Notes. The package retains strict TypeScript conventions, local `src/types.ts` remains types-only, and no Provider/Browser/Session dependency was introduced into Engine source.

Repository-wide and exact-head executable validation is still pending. The current Canvas stack repeatedly shows GitHub Actions infrastructure symptoms such as jobs with `steps=[]`, Azure log `BlobNotFound`, and enterprise Node 24 runners remaining queued. These failures happen before project test steps execute and therefore are neither N12 pass evidence nor N12 assertion failures.

## Acceptance conclusion

`REVIEW`

The implementation satisfies the intended N12 ownership and test design at source level, but acceptance requires actual repository-pinned typecheck/lint/build/coverage/focused test execution. Do not promote this node to `ACCEPTED` while CI remains unable to execute the exact head.
