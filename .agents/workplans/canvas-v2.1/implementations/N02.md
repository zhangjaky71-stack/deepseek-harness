## Current implementation

- `packages/canvas/canvas/src/migration.ts` is the durable structural decode/migration entry point for Canvas values.
- Workflow and Canvas Snapshot use `migrateStoredX()` for structural migration and `decodeX()` for migration plus current N01 invariant validation.
- Layout follows the same split: `migrateStoredCanvasLayoutSnapshot()` is structural; `decodeCanvasLayoutSnapshot()` in `layout.ts` adds the current layout invariant.
- `canvas/change`, Canvas Snapshot, Media Workflow, and Canvas Layout have explicit current versions and fail-loud unsupported schema behavior.
- Canvas-owned semantic nodes use `CORE_MEDIA_WORKFLOW_NODE_VERSIONS`; the map is intentionally limited to Core-owned node kinds.
- The frozen `image.create@v1` historical alias migrates to `image.generate@v1` and returns `CANVAS_DEPRECATED_NODE` without making the alias valid for current writers.
- Unknown/plugin node types are preserved structurally with their `type`, optional `nodeVersion`, config, and graph relationships. Canvas Core does not infer their current version.
- Current-schema object decoders reject unsupported fields instead of silently dropping durable data when a writer forgets to bump a version.
- `CanvasRunHistoryEntry` remains a Session-derived bounded compatibility/query DTO. Its decoder validates fields, lifecycle timestamps, and media-reference metadata without making History a second authority.

## V2.2 / rc.8 re-review adjustments

The original N02 review assumed Canvas Core owned the complete node type/version set. N01/N10/N12 now require an open-world node model, so that assumption was invalid.

The adjustment removes the migration-time built-in admission whitelist and separates version ownership:

```text
Canvas-owned node
→ Core migration/version policy

unknown/plugin node
→ preserve structural type@version/config
→ N10 Registry decides Definition availability
→ N12 decides validation/executability
```

This prevents a durable workflow from becoming unreadable merely because a plugin is currently absent.

## Added compatibility evidence

- `plugin-node-v1.json` freezes one workflow containing `example.custom-transform@3`.
- Migration tests require that plugin type/version/config survive direct workflow decode and nested Canvas Snapshot rebuild without consulting a plugin registry.
- A plugin node version such as `@999` is preserved rather than misclassified as a Canvas-owned future node version.
- Current Workflow/Node/Layout unknown fields are rejected.
- Layout structural migration is tested separately from current layout invariants.
- Run History DTO tests reject incompatible media metadata and impossible terminal lifecycle data.
