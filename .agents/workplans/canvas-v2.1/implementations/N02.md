# N02 Implementation — Schema migration and golden fixtures

Status: REVIEW  
Date: 2026-08-19  
Branch: `agent/canvas-n02-migrations`  
Base: `agent/canvas-n01-domain`

## Delivered

- Added `packages/canvas/canvas/src/migration.ts` as the single durable decode/migration boundary for Canvas values.
- Added stable current versions for `canvas/change`, Canvas layout, workflow schema, Canvas snapshot schema, and every V1 node kind.
- Added stable `CanvasMigrationError` codes for invalid values, unsupported historical versions, and unsupported future schema/node versions.
- Split structural migration (`migrateStoredMediaWorkflow`, `migrateStoredCanvasSnapshot`) from current relational invariants (`decodeMediaWorkflow`, `decodeCanvasSnapshot`) so the pipeline is explicitly decode → migrate → validate.
- Added separately versioned `CanvasLayoutSnapshot` and bounded `CanvasRunHistoryEntry` DTO vocabulary required by the V2.1 migration fixtures; neither is a second durable authority.
- Added append-only golden fixtures for `workflow-v1`, `snapshot-v1`, `layout-v1`, `run-history-v1`, and a frozen deprecated-node V1 shape.
- Added one deliberately retired pre-registry `image.create@v1` historical alias that migrates to `image.generate@v1` with a `CANVAS_DEPRECATED_NODE`/`deprecated` notice. The alias is not part of `MediaWorkflowNodeType`, so current writers cannot emit it.
- Added unit coverage for V1 decode, migration idempotency, future-version fail-loud behavior, deprecated-node lifecycle, structural-migration/invariant separation, layout decode, and run-history decode.
- Updated the Canvas bilingual package README and proposed Agent Note to document the migration boundary and append-only historical-data policy.

## Validation completed

- A strict local TypeScript structural check using the available compiler and dependency stubs passed for the migration implementation with `strict`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes` enabled.
- The implementation was self-reviewed against the N02 workplan: historical values are never rewritten, unknown future versions do not guess downgrades, and deprecated-node migration becomes idempotent once the runtime shape is current.
- The N02 package changes add no workspace dependency or package-graph edge beyond N01; N02 therefore does not introduce an additional lockfile/module-graph delta of its own.
