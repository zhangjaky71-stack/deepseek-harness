## Remediation audit findings and fixes

### 1. Exact catalog identity instead of type-only lookup

The original ConnectionPanel built `Map<type, definition>`. With open-world plugins this is incorrect: when v1 and v2 of the same type are installed, a historical v1 Workflow node can accidentally receive v2 ports/metadata.

N11 now adds `src/client/catalog.ts` as a Browser-local projection helper. It resolves a durable node only by the exact identity:

```text
(node.type, node.nodeVersion ?? 1)
```

There is no fallback to the newest/last same-type definition. The helper also combines the exact definition with current Host-published Canvas capabilities without recreating Registry authority.

`adapters.ts` now preserves `nodeVersion` in `CanvasFlowNode`; otherwise the visual graph path would have silently dropped the version before availability checks and fallen back to v1.

### 2. Historical unavailable nodes remain visible but cannot be mis-edited

A node whose exact definition is not installed still belongs to durable Workflow history. The Editor now keeps such a node visible but:

- does not create an editable Draft for it;
- renders a read-only Inspector diagnostic;
- does not invent ports for new Connection authoring;
- never silently binds it to another installed version.

The same read-only degradation applies when the exact definition exists but its named deployment Feature is currently disabled. This is separate from N10 `lifecycle.executable=false`: executable lifecycle controls run admission, not Editor edit permission, so N11 does not treat every non-executable installed definition as missing.

Node Library creation is now filtered by the Host catalog's `creatable`, `deprecated`, and feature metadata. Browser still maintains no second Registry and does not infer available node types from the current Workflow.

### 3. Debounce and blur use one Draft save path

The original implementation had only a 450ms debounce even though the workplan requires debounce/blur behavior. `WorkflowEditor` now has one `saveDraft(candidate)` path used by both triggers.

One in-flight key is derived from node id, base Workflow revision, name text, and config text. If blur starts a write and the pending 450ms timer later fires for the same Draft, the second path sees the same active identity and does not duplicate the Host mutation.

The save path preserves the existing CAS contract:

- Draft based on an older projected revision becomes `conflict` without overwriting current Workflow;
- invalid local JSON becomes `save-failed` before Host mutation;
- successful zero-op Draft becomes clean without creating a revision;
- accepted semantic operations are one Host transaction;
- offline/save failure leaves the Draft dirty and does not present `Saved`.

### 4. Renderer-neutral metadata remains semantic

`CanvasFlowNode` now carries `nodeVersion` in addition to id/type/label/position. This is still renderer-neutral semantic identity, not renderer-owned JSON. A later XYFlow/React Flow implementation can replace positioned cards while preserving the same Domain and catalog lookup contract.

## Open-world migration audit

The old N11 implementation record listed N10's built-in node whitelist as an outstanding blocker. That statement is stale in the current stack.

Current `migration.ts` has strict version handling only for Canvas-owned core node types and the frozen historical `image.create` alias. An unknown plugin type is retained as a non-empty string with its optional positive `nodeVersion` and config/name; migration does not invent a provider version or require the plugin to be installed. Current availability/executability remains Registry-owned. Therefore this old blocker is closed before the N11 remediation PR.

## Explicit N11 follow-up: optional node-name exact clear/Undo

The remaining known semantic gap is narrow and Host-wire-specific:

- Domain and durable migration permit optional `MediaWorkflowNode.name` and permit the string form to be empty.
- current V1 `rename-node` source-mode Host boundary requires a non-empty string;
- the existing inverse command for a node that originally had no `name` can only produce `name: ''`;
- therefore clearing a node name and exactly restoring field absence cannot be represented by the current wire operation.

N11 does **not** hide this by storing a fake durable distinction in Browser state. A future Host contract must provide an exact clear/restore operation (or equivalent explicit nullable/optional mutation semantics), with source-mode validation, apply logic, Remote schema generation, and Host/Browser round-trip tests. A temporary type-only experiment was reverted; this branch contains no half-implemented operation.

This follow-up does not change the authority model: all representable semantic edits still go to CanvasService atomically, and the unsupported field-absence case is documented rather than silently approximated.
