## V2.2 / Harness rc.8 re-review

The rc.8 compatibility and N10/N12 architecture review found a new N01 P0 issue that invalidates the old statement that no additional N01 domain design work remained.

### Finding — runtime node admission was still closed

`src/types.ts` had already introduced `MediaWorkflowNodeTypeMap` as a declaration-merge surface, but `src/domain.ts` still contained a fixed `NODE_TYPES` set and rejected any node type outside the built-in list.

That combination made the type layer look extensible while the durable runtime Domain remained closed. It conflicts with the V2.2 open-world Node Registry / Executor Registry contract and would prevent custom/plugin nodes from surviving at the Domain boundary.

### Adjustment implemented on `fix/canvas-n01-v2.2-open-world`

- `MediaWorkflowNodeType` is now an open-world string identifier.
- `MediaWorkflowNodeTypeMap` remains the known-type/declaration-merge surface for composition typing and discoverability.
- `assertMediaWorkflow()` no longer checks a built-in node whitelist.
- Domain runtime validation now requires only a non-empty node type identifier plus structural/value invariants.
- Node availability, node-version support, config schema, port compatibility, lifecycle, and executability are explicitly delegated to N10/N12.
- Domain tests add open-world custom-node acceptance and empty-type rejection.
- Product-state tests add queued→RUNNING, CANCELLED, INTERRUPTED, and old-revision terminal→READY coverage.

## Revision ownership clarification

The original workplan wording could imply N01 alone proves every `+1` revision transition. That is not possible from a single snapshot.

N01 owns snapshot/value invariants:

- safe non-negative revisions;
- workflow presence/revision relationship;
- run/output cannot target a future workflow revision;
- workflow/run/output identity relationships.

N03 owns adjacent durable transition invariants in the event fold:

- workflow mutation advances only `workflowRevision` exactly once;
- run lifecycle advances only `runRevision` exactly once;
- output selection changes neither revision.

The N01 workplan has been updated accordingly.

## `invariant.ts` ownership clarification

The package's current `src/invariant.ts` is no longer an N01 pure-value validator. Later nodes evolved it into the Session durable-stream Cordis invariant companion. N01 pure-value checks live in `domain.ts`; Session-stream invariant ownership belongs to N03/N05.

## Remaining P0 follow-up outside N01

N02 `migration.ts` still uses `MEDIA_WORKFLOW_NODE_VERSIONS/NODE_TYPES` to reject unknown plugin node identifiers. Therefore the full durable reload path is not open-world yet.

N02 must be changed so that unknown/custom nodes remain structurally readable/migratable while N10/N12 decide current availability/executability. This is intentionally not patched in the N01 adjustment branch to keep node ownership explicit.
