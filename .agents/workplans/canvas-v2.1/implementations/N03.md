# N03 Implementation — Canvas event sourcing and Host write service

Status: REVIEW — V2.2 remediation complete; repository validation pending  
Original implementation date: 2026-08-19  
V2.2 re-review/remediation: 2026-08-21  
Current remediation branch: `fix/canvas-n03-v2.2-durable-authority`  
Base: `fix/canvas-n02-v2.2-open-world-migration`

## Historical implementation

The original N03 branch established the correct architectural skeleton:

- full post-change `canvas/change` Session events;
- strict replay fold;
- Session-backed CanvasService cache;
- WorkflowRef CAS excluding runRevision;
- atomic workflow operation batches;
- invariant staging through Session precommit and postcommit notifications.

That historical implementation remains useful context, but the previous statement that N03 was blocked only by repository validation is superseded by the V2.2 re-review below.

## V2.2 re-review findings

The 2026-08-21 audit identified these blocking gaps:

1. CanvasService accepted an Agent whose `agent.session` was detached from `ctx.sessions`, allowing writes outside SessionStore publication/persistence/invariant/projection boundaries.
2. CanvasService did not independently preflight the full `CanvasChange` transition before append.
3. Durable Run vocabulary only modeled `run-start`/completed `run-complete`, while the Domain already contained failed/cancelled/interrupted states needed by N16.
4. Fold tracked reused CanvasId but not reused RunId; history and fold could disagree on the same Session.
5. Sensitive workflow-config scanning lived only in CanvasService and could be bypassed by a Host plugin calling `Session.append('canvas/change', ...)` directly.
6. Historical metadata v1 remained writable by current live append paths.
7. A non-terminal Run could be orphaned by clearing its owning Canvas.
8. Clear used only CanvasId rather than the WorkflowRef CAS fence.
9. Semantic no-op edits manufactured revisions and Session events.
10. WorkflowRef identity/revision failures were collapsed into `CANVAS_STALE_WORKFLOW_REVISION`.
11. Initial variant creation checked the variants feature but not the dedicated `canvas.variant.create` permission.
12. N03 documentation still described the V2.1 baseline and did not encode current Session commit-point semantics.

## Remediation delivered

### Exact durable authority

CanvasService now requires both exact identities:

```text
ctx.agents.get(agent.id) === agent
ctx.sessions.get(agent.session.id) === agent.session
```

A detached `Session.create()` object can no longer become a Canvas durable authority merely by registering an Agent around it.

### Service-owned transition preflight

`CanvasService.commit()` now:

```text
cloneCanvasFoldState(cache.state)
→ applyCanvasChange(staged, candidate)
→ session.append('canvas/change', candidate)
→ sync committed events into cache
```

The package invariant remains a second defensive boundary for direct append; CanvasService no longer relies on that optional companion for its own correctness.

### Run lifecycle vocabulary

`CanvasOperation` now includes current `run-update` while retaining historical `run-complete` decode/replay compatibility.

The strict fold supports:

```text
queued  → queued/running/completed/failed/cancelled/interrupted
running → running/completed/failed/cancelled/interrupted
```

and rejects running→queued plus all terminal→later lifecycle transitions.

RunId is now Session-wide unique through `CanvasFoldState.seenRunIds`, including after Canvas clear/re-create.

### Current writer vs historical reader

Historical replay remains compatible with:

- `CanvasChangeMetaV1`;
- legacy `run-complete`.

Live precommit writers must use:

- metadata schema v2 with actor/source;
- `run-update` rather than legacy `run-complete`;
- audit-safe workflow config.

The invariant now re-runs `assertCanvasWorkflowAuditSafe()` at `internal/dispatch`, so another Host plugin cannot bypass the durable credential/binary boundary by calling Session.append directly.

### Mutation semantics

- clear now accepts `WorkflowRef`, not only CanvasId;
- clear rejects a current non-terminal Run;
- semantic workflow no-ops return current state without revision/event growth;
- CanvasId mismatch → `CANVAS_NOT_FOUND`;
- workflowId mismatch → `CANVAS_WORKFLOW_ID_MISMATCH`;
- workflowRevision mismatch → `CANVAS_STALE_WORKFLOW_REVISION`;
- initial `currentVariantId` creation requires `canvas.variant.create` in addition to `canvas.edit`.

## Test/source updates

Updated source tests cover:

- exact live Agent + Session and detached-session rejection;
- cold replay/live cache equality;
- operation-batch rollback;
- semantic no-op suppression;
- identity-specific CAS errors;
- clear CAS and active-run protection;
- Session precommit veto leaving log/cache unchanged;
- all terminal Run states;
- RunId reuse rejection;
- running→queued rejection;
- historical run-complete replay;
- live metadata v1 rejection with historical v1 late-load compatibility;
- direct-append sensitive workflow rejection;

The affected Harness tests were migrated from detached `Session.create()` fixtures to live `SessionStore` sessions where CanvasService durability is under test.
