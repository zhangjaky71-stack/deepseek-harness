# N03 Implementation — Canvas event sourcing and Host write service

Status: REVIEW  
Date: 2026-08-19  
Branch: `agent/canvas-n03-event-sourcing-service`  
Base: `agent/canvas-n02-migrations`

## Delivered

- Added durable `canvas/change` Session events carrying one complete post-change `CanvasSnapshot`; clear events carry `canvas: null`.
- Added a versioned `CanvasChangeMeta` seed so N04 can add actor/audit metadata without inventing authorization inside N03.
- Added strict `decodeCanvasChange`, `applyCanvasChange`, `applyCanvasEvent`, and `foldCanvas` replay logic with transition-specific workflow/run/output checks.
- Replaced the N01/N02 empty invariant companion with an independent Canvas-stream invariant that stages candidate fold state during `internal/dispatch` and publishes it only after the matching committed `session/event`.
- Added `CanvasService` as the default package service and `ctx.canvas` Host mutation owner with per-Session replay caches synchronized by Session sequence.
- Added `WorkflowRef` CAS on Canvas id, workflow id, and `workflowRevision`; `runRevision` is deliberately outside the semantic edit fence.
- Added atomic `WorkflowEditOperation[]` application for add/remove node, replace config, rename node/workflow, connect/disconnect, and output-node selection. A batch validates once as a complete workflow and appends one event only after all operations succeed.
- Added `create`, `replaceWorkflow`, `editWorkflow`, `selectOutput`, `clear`, and current-state `get` service methods. Provider execution and Browser Remote wrappers remain later nodes.
- Added stable pre-commit service errors for stale revisions, missing/current identity failures, invalid edit batches, and output selection.
- Added strict replay vocabulary for `run-start` and `run-complete` so N03 can prove `runRevision` independence and output selection without implementing Jobs or Provider execution.
- Added unit coverage for cold replay/live equality, atomic rollback, stale CAS, runRevision independence, complete operation batches, replacement identity, output selection, clear/null replay, repeated cache reads, strict fold transitions, and invariant pre-commit rejection.
- Updated the bilingual package README and Session media Canvas Agent Note with the Session authority, commit-point, CAS, and metadata-versioning decisions.

## Validation completed

- A strict local TypeScript structural check using TypeScript 5.8.3 and dependency stubs passed for the N03 source files with `strict`, `noUncheckedIndexedAccess`, and `exactOptionalPropertyTypes` enabled, including the runtime invariant companion.
- A separate strict TypeScript structural check passed for the N03 service/fold/invariant test sources after correcting closure narrowing around the current output reference.
- Static review confirmed that `CanvasService.commit()` calls `session.append('canvas/change', ...)` before synchronizing or publishing its cache, and candidate workflow state remains detached until the append succeeds.
- Static review confirmed that a workflow-operation batch increments `workflowRevision` once and has one Session append point after final workflow validation.
- Static review confirmed that `WorkflowRef` contains no `runRevision`, while strict replay permits an older run snapshot to remain current after a semantic workflow revision advances.
- N03 adds Host dependencies on agent, Session, and Harness error vocabulary; the package tsconfig and package manifest declare those edges.
