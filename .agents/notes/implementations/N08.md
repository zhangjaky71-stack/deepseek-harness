# N08 — Canvas Interaction Context implementation record

## Scope delivered

N08 connects Browser-local Canvas selection to the exact next ordinary Agent prompt without turning selection into durable Canvas domain state.

Implemented surface:

- per-session Browser-local selected node / selected edge / selected asset state;
- current-output candidate focus;
- `CanvasRegionSelection` DTO/store seam;
- send-time snapshot anchored to `{ canvasId, workflowId, workflowRevision }`;
- exact prompt correlation through the ordinary `session.prompt` RPC id;
- Host stage/discard Remote namespace `canvasInteraction`;
- exact rpcId → admitted user-message id binding;
- model-visible plugin context insertion at `agent/pre-step`;
- stale and unavailable revision guidance;
- same-Session durable asset provenance validation;
- selectable Editor node/edge cards and Minimal/Editor output candidates;
- unit, bridge, bundle, and built-LIB Remote composition coverage.

This node deliberately does **not** implement Canvas Agent tools, DAG mutation, region drawing, masks, provider execution, or Run/Cancel behavior.

## Final data flow

```text
Canvas UI-local selection
  ↓ synchronous snapshot at composer send boundary
ui-conversation prompt preparation provider
  ↓
AbstractApiClient mints ordinary session.prompt rpcId
  ↓ before envelope observation / POST
remote.canvasInteraction.stage(sessionId, { rpcId, context })
  ↓
normal session.prompt request (wire payload unchanged)
  ↓
Host creates the ordinary user message with source.rpcId
  ↓ agent/inbox/inserted
CanvasInteractionBridge binds rpcId → exact user message id
  ↓ possibly waits in Queue
agent/pre-step
  ↓ only if the exact message survives downstream pre-step policy
logged plugin snapshot message + exact user prompt
  ↓
normal Agent loop writes both to Session before model request
```

Browser selection itself never becomes `canvas/change`, `canvas/layout-change`, Session Projection, or Workflow state. The plugin-context message does become Session history because it is model-visible content actually supplied to that turn.

## Why the ordinary prompt RPC id is the correlation token

A pure timing-based “stage then take the next inbox message” design is unsafe under concurrent prompt admission and existing Queue work. The ordinary fetch carrier already mints a unique `rpcId`, and the Host already records that exact id in the corresponding durable user-message source. N08 therefore reuses this existing identity rather than inventing another wire field.

`AbstractApiClient.sessions.prompt()` gained an optional client-only preparation callback. `callUnary()` executes it after minting `rpcId` but before envelope observation or transport. `Session.prompt()` threads that callback only for ordinary sessions; subagent continuations reject request-local preparation rather than silently dropping it.

The Host prompt payload and API schema remain unchanged.

## Browser send-time semantics

`ui-conversation` owns a feature-neutral prompt preparation registry. Providers are sampled synchronously at the user send boundary, before image serialization can yield. This means selection changed while upload work is in flight cannot backwash into the already-submitted prompt.

A preparation stages against the exact minted RPC id. Prompt admission failure triggers best-effort discard. If preparation fails before transport, the prompt is not sent.

`ui-canvas` registers one preparation provider when generated `remote.canvasInteraction` is available. With no concrete selection it returns no preparation, so no Canvas context is fabricated.

## Selection anchoring and stale behavior

Every semantic selection records the Canvas/workflow identity and workflow revision observed at click time.

- Same Canvas/workflow + same revision: selected node/edge ids are membership-checked on the Host.
- Same Canvas/workflow + newer current revision: the sampled revision is retained and the context is marked `STALE`; the Agent is instructed to call `canvas_read` before mutating sampled workflow targets.
- Canvas/workflow identity replacement before send: the Browser builder drops the old selection rather than rebinding it to a different document.
- Canvas/workflow becomes unavailable after prompt admission but before claim: the admitted prompt still runs with `STALE/UNAVAILABLE` context rather than failing after acceptance.

Current-output focus and durable assets have different semantics. `{ runId, assetIndex }` focus is emitted only while that run/index is current. The durable selected asset ref remains usable after later output changes.

## Asset provenance

Browser-supplied selected assets and region/mask assets are not accepted solely because their DTO shape is valid. Stage scans this exact Session's historical `canvas/change` outputs and requires an exact immutable-reference fingerprint match. This prevents interaction context from naming an arbitrary or cross-Session asset.

## Host service topology

The durable `CanvasService` in `src/runtime.ts` remains unchanged and continues to own namespace `canvas`.

N08 adds `CanvasInteractionService` as a second **direct** `TypertRemoteService` in the same `@deepseek-ai/dsh-canvas` package, under namespace `canvasInteraction`. This is intentional: the Typert generator recognizes direct gateway-service inheritance, and its emitter can merge multiple service descriptors from one package into the same generated `./remote` contribution.

The shipped base bundle adds one Host row:

```yaml
- id: canvas-interaction
  name: '@deepseek-ai/dsh-canvas/interaction-service'
```

`api-remotes` still mounts the existing single `@deepseek-ai/dsh-canvas/remote` contribution. No new workspace package or lockfile importer is introduced.

## Host bridge lifecycle

`CanvasInteractionBridge` owns process-local correlation only:

- staged key: `agentId + rpcId`;
- bound key: `agentId + messageId`;
- stage TTL: 30 seconds;
- `agent/inbox/inserted`: exact rpcId bind;
- `agent/inbox/discarded`: drop binding;
- `agent/disposed`: clear all rows for that Agent;
- plugin disposal: clear all staged timers/maps;
- `agent/pre-step`: await downstream policy, then decorate only surviving exact messages and consume their bindings.

A rejected or removed prompt cannot leak its selection to a later turn.

## Model-visible form

The model-visible context is one user-role plugin snapshot message:

```ts
{
  source: {
    kind: 'plugin',
    plugin: 'canvas-interaction',
    form: 'snapshot',
    sections: [{ name: 'Canvas interaction', text }],
  },
  content: [{ type: 'text', text }],
}
```

`ui-conversation` therefore renders it as context rather than an ordinary human chat bubble. The renderer includes sampled/current revision state and only the selection fields that actually exist. It explicitly tells the model not to invent a target when a field is absent.

## Remaining limits

- `canvas_read` / edit / run Agent tools are later nodes, so N08 only grounds referents and emits stale guidance.
- visual region/mask authoring is not implemented; only the DTO/store seam exists.
- Interaction correlation is process-local by design. If the Host process dies before a staged/bound prompt reaches `pre-step`, the ephemeral selection context is lost; the durable user prompt remains governed by ordinary Session recovery.
- Run/Cancel and actual media execution remain outside N08.
